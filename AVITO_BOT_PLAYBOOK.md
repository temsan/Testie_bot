# Плейбук: квалификация лидов в Avito Messenger через сессию в Chrome

Этот файл описывает алгоритм ОДНОГО тика мониторинга. Используется вместе
с `/loop`: Claude выполняет эти шаги каждый раз, когда просыпается по таймеру.

Состояние диалогов хранится в `avito_state.json` (в .gitignore, не коммитится).
Правила ниши и квалификации берутся из живого конфига проекта командой:

```
PYTHONIOENCODING=utf-8 python -c "import json, storage; print(json.dumps(storage.get_config(), ensure_ascii=False))"
```

Так изменения, сделанные через `/admin` в Telegram-версии бота, сразу
применяются и к Avito-диалогам — конфиг один на обе платформы.

## Формат avito_state.json

```json
{
  "<url или уникальный идентификатор чата>": {
    "title": "Имя собеседника / объявление",
    "stage": "NEED | BUDGET | TIMELINE | CONTACT | DONE",
    "need": "...",
    "budget": "...",
    "timeline": "...",
    "contact": "...",
    "score": 0,
    "qualified": true,
    "last_seen_text": "последнее увиденное сообщение лида (для дедупликации)"
  }
}
```

## Шаги тика

1. Открыть/обновить вкладку `https://www.avito.ru/profile/messenger`.
2. Нажать фильтр «Непрочитанные» (или посмотреть список чатов на бейджи непрочитанного).
3. Для каждого чата с новым сообщением от лида (не от нас):
   a. Открыть чат, прочитать текст последних сообщений (`get_page_text`).
   b. Найти состояние чата в `avito_state.json` по идентификатору чата (URL чата содержит id).
   c. Сравнить последнее сообщение лида с `last_seen_text` — если совпадает, лид ничего
      нового не написал, пропустить (защита от повторной обработки).
   d. Определить стадию и сформировать ответ по логике ниже.
   e. Напечатать ответ в поле ввода чата и отправить (Enter или кнопка отправки).
   f. Обновить `avito_state.json`: новую стадию, накопленные данные, `last_seen_text`.
4. Залогировать в конце тика одной строкой: сколько чатов обработано, сколько
   лидов квалифицировано/не квалифицировано за этот тик.

## Логика стадий (повторяет bot.py, адаптировано под свободный текст без кнопок)

- **Нет состояния (первое сообщение лида в чате)** → стадия `NEED`.
  Отправить `cfg["greeting"]` (уже содержит приветствие + вопрос о потребности).

- **Стадия `NEED`, пришёл ответ** → сохранить как `need`. Отправить
  `cfg["budget_question"]` + список `cfg["budget_options"]` пронумерованным
  списком (в Avito нет кнопок, только текст), с припиской "напишите номер
  варианта или ответьте свободно". Стадия → `BUDGET`.

- **Стадия `BUDGET`, пришёл ответ** → сопоставить ответ лида с одним из
  `cfg["budget_options"]` (по номеру, если писал цифру, иначе по смыслу —
  интерпретировать свободный текст в ближайший вариант). Сохранить как
  `budget`. Отправить `cfg["timeline_question"]` + `cfg["timeline_options"]`
  тем же пронумерованным способом. Стадия → `TIMELINE`.

- **Стадия `TIMELINE`, пришёл ответ** → сопоставить с `cfg["timeline_options"]`,
  сохранить как `timeline`. Посчитать
  `score = budget_scores[budget] + timeline_scores[timeline]`,
  `qualified = score >= cfg["QUALIFY_THRESHOLD"]`.
  - Если `qualified` → отправить `cfg["qualified_message"]`. Стадия → `CONTACT`.
  - Иначе → отправить `cfg["not_qualified_message"]`. Стадия → `DONE`.

- **Стадия `CONTACT`, пришёл ответ** → сохранить как `contact`. Отправить
  `cfg["thanks_after_contact"]`. Стадия → `DONE`.

- **Стадия `DONE`** → новых сообщений от лида в этой стадии не ожидается;
  если лид написал что-то ещё, ответить `cfg["restart_hint"]`-подобным
  сообщением ("данные переданы менеджеру, скоро свяжемся") и не трогать состояние.

## Деплой на Railway (постоянный процесс, без открытого Chrome)

`avito_bot.py` поддерживает два режима подключения к браузеру
(см. `get_browser_and_context` в коде):

- **CDP** (`CDP_URL`) — для локальной разработки, требует открытого Chrome
  с `--remote-debugging-port=9222`.
- **storage_state** (`AVITO_STORAGE_STATE_B64` / `AVITO_STORAGE_STATE_PATH`)
  — headless Chromium стартует с нуля и подгружает заранее сохранённые
  cookies авторизованной сессии. Именно этот режим нужен для хостинга —
  Railway не имеет доступа к вашему локальному Chrome.

### Шаги

1. **Локально** (у себя, не на хостинге): открыть Chrome с
   `--remote-debugging-port=9222`, залогиниться на avito.ru как продавец,
   выполнить `python export_avito_session.py`. Скрипт сохранит
   `avito_storage_state.json` и напечатает его base64-представление —
   именно оно, а не пароль, идёт дальше на хостинг.
2. В Railway создать новый проект → Deploy from GitHub repo → выбрать этот
   репозиторий (в нём уже есть `Dockerfile`, Railway подхватит его
   автоматически).
3. Задать переменные окружения проекта в Railway:
   - `AVITO_STORAGE_STATE_B64` — значение из шага 1
   - `OPENROUTER_API_KEY`
   - `OPENROUTER_MODEL` (опционально, дефолт в коде —
     `meta-llama/llama-3.1-8b-instruct:free`)
   - `POLL_INTERVAL_SECONDS` (опционально, дефолт 30)
   - `AVITO_STATE_DIR=/data` (если подключён volume, см. ниже)
4. **Volume для `avito_state.json`** (рекомендуется): без него состояние
   диалогов (стадии, накопленные ответы, дедупликация по
   `last_seen_text`) будет теряться при каждом рестарте контейнера. В
   Railway: Settings → Volumes → примонтировать на `/data`, задать
   `AVITO_STATE_DIR=/data`.
5. Сессия Avito рано или поздно истечёт (cookies разлогинят бота — в
   логах появятся ошибки загрузки страницы messenger). Тогда шаг 1
   нужно повторить и обновить `AVITO_STORAGE_STATE_B64` в Railway.
6. Сервис — фоновый воркер, HTTP-порт ему не нужен (Railway это
   поддерживает наравне с веб-сервисами).

## Деплой на Fly.io (альтернатива Railway)

Тот же принцип (см. режимы выше), в репозитории уже есть `fly.toml` рядом
с `Dockerfile`. Деплой — с вашей машины через `flyctl` (в этой сессии
доступа к fly.io нет — egress этой песочницы блокирует произвольные
хосты, деплоить нужно локально).

### Шаги

1. Тот же шаг 1, что и для Railway: локально получить
   `AVITO_STORAGE_STATE_B64` через `export_avito_session.py`.
2. Установить `flyctl` (https://fly.io/docs/flyctl/install/), `fly auth login`.
3. В `fly.toml` поменять `app = "avito-bot"` на своё уникальное имя
   (и `primary_region`, если нужно другой).
4. Создать приложение и volume (10-минутный полный размер free allowance
   обычно хватает под `avito_state.json`):
   ```
   fly apps create <ваше-имя-приложения>
   fly volumes create avito_data --region ams --size 1
   ```
5. Задать секреты (не коммитятся, хранятся в Fly, а не в репозитории):
   ```
   fly secrets set \
     AVITO_STORAGE_STATE_B64="<значение из шага 1>" \
     OPENROUTER_API_KEY="<ваш ключ>"
   ```
6. Деплой: `fly deploy`.
7. Логи: `fly logs`. Когда сессия Avito истечёт (см. ниже) — повторить
   шаг 1 и обновить секрет: `fly secrets set AVITO_STORAGE_STATE_B64="..."`.

Сессия Avito рано или поздно истечёт (cookies разлогинят бота — в логах
появятся ошибки загрузки страницы messenger) — тогда шаг 1 нужно повторить
и обновить `AVITO_STORAGE_STATE_B64` на выбранном хостинге (Railway или Fly).

## Деплой на Fly.io с интерактивным логином (без export_avito_session.py)

Альтернатива варианту выше: вместо экспорта cookies с локальной машины —
постоянный Chrome с виртуальным рабочим столом (Xvfb + x11vnc + noVNC)
прямо на Fly, в том же контейнере, что и avito_bot.py. Заходите в него один
раз через браузер и логинитесь на avito.ru как обычно — Chrome работает
там же, где будет работать бот, повторный экспорт/импорт сессии не нужен.

Файлы: `Dockerfile.desktop`, `docker/supervisord.conf`,
`docker/start-chrome.sh`, `docker/wait-for-cdp.sh`, `fly.desktop.toml`.
Собрать и запустить это в текущей облачной сессии Claude Code невозможно
(нет доступа к fly.io) — конфигурация не проверялась вживую, при первом
`fly deploy` возможны мелкие правки (например, если пакет `chromium`
называется иначе в конкретном образе).

**Важно про безопасность**: порт noVNC (6080) в `fly.desktop.toml`
намеренно НЕ публикуется наружу — доступ к нему означает полный контроль
над вашим Chrome и, соответственно, над перепиской и аккаунтом продавца.
Заходить нужно только через приватный туннель `fly proxy`, не через
публичный `[http_service]`.

### Шаги

1. Установить `flyctl`, `fly auth login` (если ещё не сделано).
2. В `fly.desktop.toml` поменять `app = "avito-bot-desktop"` на своё
   уникальное имя.
3. Создать приложение и volume для профиля Chrome + `avito_state.json`:
   ```
   fly apps create <ваше-имя-приложения>
   fly volumes create avito_desktop_data --region ams --size 3 \
     --app <ваше-имя-приложения>
   ```
4. Задать секреты:
   ```
   fly secrets set OPENROUTER_API_KEY="<ваш ключ>" --app <ваше-имя-приложения>
   ```
5. Деплой с указанием конфига:
   ```
   fly deploy --config fly.desktop.toml --app <ваше-имя-приложения>
   ```
6. Открыть приватный туннель к noVNC (эта команда держит терминал
   открытым, пока туннель нужен):
   ```
   fly proxy 6080:6080 -a <ваше-имя-приложения>
   ```
7. В своём браузере открыть `http://localhost:6080/vnc.html` (кнопка
   Connect, пароль не нужен — `x11vnc -nopw`, канал уже приватный через
   `fly proxy`). Внутри — реальный Chrome, открытый на
   `avito.ru/profile/messenger`. Залогиниться как обычно (логин/пароль/SMS
   вводятся прямо в этом окне, никуда, кроме Fly, не уходят).
8. После логина закрыть туннель (Ctrl+C у `fly proxy`) — доступ снаружи и
   так был только у вас, но держать его открытым без необходимости не
   стоит. `avito_bot.py` внутри контейнера уже подключён к этому же Chrome
   по CDP (`http://127.0.0.1:9222`) и начнёт обрабатывать чаты сразу после
   логина.
9. Логи: `fly logs -a <ваше-имя-приложения>`.
10. Когда сессия Avito истечёт — повторить шаги 6-7 (переоткрыть туннель,
    залогиниться заново в том же окне noVNC).

## Важно

- Не отправлять сообщения в чаты, которые не являются лидами (например,
  системный чат "Поддержка Авито") — фильтровать по названию/типу собеседника.
- Не изобретать информацию о товаре/услуге вне конфига.
- Один вопрос за раз, как того требует сценарий.
- Если разметка Avito Messenger не даёт понять, кто автор сообщения (лид или
  мы), делать zoom/screenshot чата и разбираться по расположению (свои
  сообщения обычно справа, входящие — слева) прежде чем отвечать.
