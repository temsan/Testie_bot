# Бот-консультант — валидация и квалификация лидов

Тестовое задание: Telegram-бот, который ведёт диалог с потенциальным клиентом,
задаёт квалифицирующие вопросы, определяет целевой лид или нет, и либо
предлагает следующий шаг (звонок/встреча), либо вежливо закрывает нецелевой диалог.

Бот сделан **универсальным**: под конкретную нишу (недвижимость, авто, услуги и т.п.)
он адаптируется без единой строчки кода — через встроенную админ-панель (`/admin`)
с пошаговым мастером и кнопками, либо вручную через `config.py`.

> Платформа: Telegram (демо-прототип). У Avito нет мгновенно выдаваемого Bot API —
> доступ к Avito Messenger API требует регистрации в партнёрской программе на
> developers.avito.ru и одобрения заявки, поэтому для теста используется Telegram;
> логика скоринга и весь конфиг платформонезависимы и переносятся на Avito API 1-в-1.

## Сценарий диалога (дерево)

```
/start
  └─ Приветствие + открытый вопрос о потребности
       └─ [ответ: свободный текст]
            └─ Вопрос про бюджет (кнопки с диапазонами)
                 └─ [выбор варианта]
                      └─ Вопрос про сроки (кнопки со сроками)
                           └─ [выбор варианта]
                                ├─ РАСЧЁТ СКОРИНГА (бюджет + сроки)
                                │
                                ├─ score >= порога → ЦЕЛЕВОЙ ЛИД
                                │     └─ Сообщение с предложением созвона
                                │          └─ Запрос контакта (телефон/мессенджер + удобное время)
                                │               └─ Благодарность, конец диалога
                                │
                                └─ score < порога → НЕЦЕЛЕВОЙ ЛИД
                                      └─ Вежливое закрытие диалога, подсказка написать позже
```

`/cancel` — прерывает диалог на любом шаге.

## Логика квалификации

Простая скоринговая модель в `config.py` → `QUALIFICATION_RULES`:

- каждому варианту ответа на "бюджет" и "сроки" присвоен вес (0–3);
- сумма весов сравнивается с порогом `QUALIFY_THRESHOLD` (по умолчанию 3 из 6 максимума);
- если сумма ≥ порога — лид считается целевым.

Пороги и веса — просто числа в конфиге, подстраиваются под нишу без правки кода.

## Как адаптировать под другую нишу

### Вариант А — через админ-панель бота (рекомендуется, без кода)

1. Добавить свой Telegram user_id в `ADMIN_IDS` в `.env` (узнать id — написать [@userinfobot](https://t.me/userinfobot)).
2. В боте набрать `/admin`.
3. Нажать «🧙 Настроить нишу (мастер)» и пройти 12 шагов с кнопками:
   название ниши → приветствие → вопрос о бюджете → варианты бюджета →
   веса вариантов бюджета (кнопки 0–3) → вопрос о сроках → варианты сроков →
   веса вариантов сроков → порог квалификации (кнопки 0–6) → сообщение
   целевому лиду → сообщение нецелевому лиду → благодарность после контакта.
4. На последнем шаге проверить сводку и нажать «💾 Сохранить» — новый
   сценарий применяется сразу, без перезапуска бота.

Остальные пункты меню `/admin`: «✏️ Изменить поле» — поправить одно
сообщение/вопрос/порог без прохождения мастера заново; «👀 Текущий конфиг» —
посмотреть, что сейчас активно; «📋 Последние лиды» — последние 10
зафиксированных диалогов (need/бюджет/сроки/score/контакт); «🔄 Сбросить
на дефолт» — вернуть значения из `config.py`.

Если лид отвечает на вопрос о бюджете/сроках свободным текстом вместо
нажатия кнопки, бот сам подбирает ближайший по смыслу вариант из списка
(`storage.match_option`), чтобы не терять баллы скоринга из-за формулировки.

### Вариант Б — вручную, правкой файла

Откройте `config.py` и замените:

- `NICHE["greeting"]`, `NICHE["budget_options"]`, `NICHE["timeline_options"]` — под тематику
  (например, для авто: "До 500 000 ₽ / 500 000–1 500 000 ₽ / Более 1 500 000 ₽");
- `QUALIFICATION_RULES` — веса и порог квалификации под ожидаемые чеки в нише.

Код бота (`bot.py`) при этом не меняется. Если рядом уже есть `niche_config.json`
(создан мастером из /admin), он имеет приоритет над `config.py` — удалите файл
или нажмите «🔄 Сбросить на дефолт» в `/admin`, чтобы вернуться к значениям из кода.

## Запуск

1. Установить зависимости:
   ```
   pip install -r requirements.txt
   ```
2. Получить токен бота у [@BotFather](https://t.me/BotFather) (`/newbot`).
3. Скопировать `.env.example` в `.env`, вписать токен и (опционально) свой
   Telegram user_id в `ADMIN_IDS` для доступа к `/admin`:
   ```
   BOT_TOKEN=123456:ABC-...
   ADMIN_IDS=123456789
   ```
4. Запустить:
   ```
   python bot.py
   ```
5. Написать боту `/start` в Telegram (диалог с клиентом) или `/admin` (панель настройки).

## Бесплатный деплой (Render, без привязки карты)

Бот сам определяет режим: локально — обычный polling, на Render — webhook
(через переменные окружения `RENDER_EXTERNAL_URL`/`PORT`, которые платформа
подставляет автоматически). Код бота при этом не меняется.

1. Запушить репозиторий на GitHub (уже сделано, если работаете из этого проекта).
2. Зайти на [render.com](https://render.com), зарегистрироваться через GitHub
   (карта не требуется для free-плана).
3. New → Blueprint → выбрать этот репозиторий — Render подхватит `render.yaml`.
4. В форме создания заполнить переменные окружения:
   - `BOT_TOKEN` — токен от @BotFather;
   - `ADMIN_IDS` — ваш Telegram user_id (через запятую, если админов несколько).
5. Нажать Apply/Deploy. Через 1–2 минуты бот будет доступен в Telegram.

Особенности free-плана Render: сервис засыпает после ~15 минут без запросов
и просыпается по первому входящему сообщению (первый ответ бота может
задержаться на несколько секунд — это нормально для бесплатного тарифа).

## Что не входит (по ТЗ тестового)

- интеграция с реальными данными/CRM;
- платёжные и банковские сценарии;
- полноценная БД — лиды хранятся в плоском `leads.json` (в `.gitignore`,
  создаётся автоматически), для прод-версии легко подключить БД или Google Sheets.
