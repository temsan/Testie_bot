# Бот-консультант — валидация и квалификация лидов

Тестовое задание: Telegram-бот, который ведёт диалог с потенциальным клиентом,
задаёт квалифицирующие вопросы, определяет целевой лид или нет, и либо
предлагает следующий шаг (звонок/встреча), либо вежливо закрывает нецелевой диалог.

Бот сделан **универсальным**: под конкретную нишу (недвижимость, авто, услуги и т.п.)
он адаптируется без единой строчки кода — через встроенную админ-панель (`/admin`)
с пошаговым мастером и кнопками, либо вручную через `config.py`.

> Платформа: Telegram (демо-прототип). У Avito нет мгновенно выдаваемого Bot API —
> доступ к Avito Messenger API требует регистрации в партнёрской программе на
> developers.avito.ru и одобрения заявки, поэтому для теста используется Telegram;
> логика скоринга и весь конфиг платформонезависимы и переносятся на Avito API 1-в-1.

## Сценарий диалога

Диалог ведёт LLM (бесплатная модель через OpenRouter) — живой разговор, а не
жёсткая анкета с кнопками. Клиент пишет свободным текстом, бот сам решает,
когда нужно уточнить потребность, спросить бюджет и сроки:

```
/start
  └─ Приветствие (текст из config.py)
       └─ Свободный диалог с LLM: уточняет потребность → бюджет → сроки
            └─ Как только бюджет и сроки понятны — отдельный запрос к LLM
               сводит их к точным вариантам из config.py (не сама беседа,
               а служебный JSON-разбор — надёжнее на маленьких моделях)
                 ├─ РАСЧЁТ СКОРИНГА в Python (бюджет + сроки), не LLM
                 │
                 ├─ score >= порога → ЦЕЛЕВОЙ ЛИД
                 │     └─ Сообщение с предложением созвона (текст из config.py)
                 │          └─ Запрос контакта — следующее сообщение клиента
                 │             сохраняется как контакт напрямую (без LLM)
                 │               └─ Благодарность, конец диалога
                 │
                 └─ score < порога → НЕЦЕЛЕВОЙ ЛИД
                       └─ Вежливое закрытие диалога (текст из config.py)
```

`/cancel` — прерывает диалог на любом шаге. После каждого завершения диалога
показывается кнопка «🚀 Оставить заявку» для повторного захода.

LLM используется только для естественного разговора и разбора свободного
текста в один из готовых вариантов config.py — сам скоринг (сумма весов
бюджет+сроки ≥ порога) считается детерминированно в Python, чтобы не
зависеть от математики бесплатной модели.

## Логика квалификации

Простая скоринговая модель в `config.py` → `QUALIFICATION_RULES`:

- каждому варианту ответа на "бюджет" и "сроки" присвоен вес (0–3);
- сумма весов сравнивается с порогом `QUALIFY_THRESHOLD` (по умолчанию 3 из 6 максимума);
- если сумма ≥ порога — лид считается целевым.

Пороги и веса — просто числа в конфиге, подстраиваются под нишу без правки кода.

## Как адаптировать под другую нишу

### Вариант А — через админ-панель бота (рекомендуется, без кода)

1. Добавить свой Telegram user_id в `ADMIN_IDS` в `.env` (узнать id — написать [@userinfobot](https://t.me/userinfobot)).
2. В боте набрать `/admin`.
3. Нажать «🧙 Настроить нишу (мастер)» и пройти 12 шагов с кнопками:
   название ниши → приветствие → вопрос о бюджете → варианты бюджета →
   веса вариантов бюджета (кнопки 0–3) → вопрос о сроках → варианты сроков →
   веса вариантов сроков → порог квалификации (кнопки 0–6) → сообщение
   целевому лиду → сообщение нецелевому лиду → благодарность после контакта.
4. На последнем шаге проверить сводку и нажать «💾 Сохранить» — новый
   сценарий применяется сразу, без перезапуска бота.

Остальные пункты меню `/admin`: «✏️ Изменить поле» — поправить одно
сообщение/вопрос/порог без прохождения мастера заново; «👀 Текущий конфиг» —
посмотреть, что сейчас активно; «📋 Последние лиды» — последние 10
зафиксированных диалогов (need/бюджет/сроки/score/контакт); «🔄 Сбросить
на дефолт» — вернуть значения из `config.py`.

Если лид отвечает на вопрос о бюджете/сроках свободным текстом вместо
нажатия кнопки, бот сам подбирает ближайший по смыслу вариант из списка
(`storage.match_option`), чтобы не терять баллы скоринга из-за формулировки.

### Вариант Б — вручную, правкой файла

Откройте `config.py` и замените:

- `NICHE["greeting"]`, `NICHE["budget_options"]`, `NICHE["timeline_options"]` — под тематику
  (например, для авто: "До 500 000 ₽ / 500 000–1 500 000 ₽ / Более 1 500 000 ₽");
- `QUALIFICATION_RULES` — веса и порог квалификации под ожидаемые чеки в нише.

Код бота (`bot.py`) при этом не меняется. Если рядом уже есть `niche_config.json`
(создан мастером из /admin), он имеет приоритет над `config.py` — удалите файл
или нажмите «🔄 Сбросить на дефолт» в `/admin`, чтобы вернуться к значениям из кода.

## Запуск

1. Установить зависимости:
   ```
   pip install -r requirements.txt
   ```
2. Получить токен бота у [@BotFather](https://t.me/BotFather) (`/newbot`).
3. Получить бесплатный ключ на [openrouter.ai/keys](https://openrouter.ai/keys) —
   им бот ведёт живой диалог с клиентом.
4. Скопировать `.env.example` в `.env`, вписать токен, ключ OpenRouter и
   (опционально) свой Telegram user_id в `ADMIN_IDS` для доступа к `/admin`:
   ```
   BOT_TOKEN=123456:ABC-...
   ADMIN_IDS=123456789
   OPENROUTER_API_KEY=sk-or-v1-...
   ```
5. Запустить:
   ```
   python bot.py
   ```
6. Написать боту `/start` в Telegram (диалог с клиентом) или `/admin` (панель настройки).

## Бесплатный деплой без привязки карты

⚠️ У Render free-план сейчас требует привязать карту (даже без списания
денег) — поэтому для полностью безкарточного бесплатного хостинга
используйте **PythonAnywhere** (ниже). Код для Render (`render.yaml`,
webhook-режим в `bot.py`) оставлен в проекте на случай, если вы всё же
привяжете карту или деплой пойдёт на другой PaaS с похожим поведением
(Railway, Fly.io и т.п. — там тот же принцип: `RENDER_EXTERNAL_URL`/`PORT`
можно заменить на `WEBHOOK_URL`/`PORT` в `.env`).

### PythonAnywhere (рекомендуется — без карты)

Free-тариф даёт один постоянно работающий веб-апп с доступом к
`api.telegram.org` (он в белом списке для бесплатных аккаунтов).
Ограничение: раз в 3 месяца нужно зайти в аккаунт и нажать «продлить»
веб-апп, иначе он засыпает — карта всё равно не требуется.

1. Зарегистрироваться на [pythonanywhere.com](https://www.pythonanywhere.com)
   (Beginner/free-аккаунт, карта не нужна).
2. В Bash-консоли PythonAnywhere:
   ```
   git clone https://github.com/temsan/Testie_bot.git
   cd Testie_bot
   pip install --user -r requirements.txt
   ```
3. Создать `.env` (через `nano .env` в той же папке):
   ```
   BOT_TOKEN=...
   ADMIN_IDS=577682
   OPENROUTER_API_KEY=sk-or-v1-...
   ```
   Если Telegram API/OpenRouter не отвечают (внешний доступ free-аккаунтов
   идёт через прокси PythonAnywhere и ограничен белым списком доменов),
   добавить туда же:
   ```
   HTTPS_PROXY=http://proxy.server:3128
   ```
   ⚠️ `openrouter.ai`, в отличие от `api.telegram.org`, может не входить в
   белый список бесплатных аккаунтов — если после деплоя бот отвечает на
   `/start`, но не продолжает диалог, проверьте
   `temsan.pythonanywhere.com.error.log` на ошибки соединения с OpenRouter.
4. Вкладка **Web** → *Add a new web app* → *Manual configuration* → Python
   (версия как в вашем окружении, например 3.10).
5. В том же разделе Web открыть **WSGI configuration file** и заменить его
   содержимое на:
   ```python
   import sys
   path = "/home/<ваш-username>/Testie_bot"
   if path not in sys.path:
       sys.path.insert(0, path)
   from wsgi_app import flask_app as application
   ```
6. Нажать **Reload** на странице Web.
7. В Bash-консоли один раз выполнить (подставив ваш адрес):
   ```
   python set_webhook.py https://<ваш-username>.pythonanywhere.com
   ```
8. Написать боту `/start` в Telegram — должен ответить.

Если конфиг меняется через `/admin` или правится `config.py` — после
`git pull` на PythonAnywhere не забудьте нажать **Reload** на странице Web,
чтобы веб-апп подхватил новый код (Flask-процесс держит `Application` в
памяти, а не перечитывает файлы на лету, в отличие от `niche_config.json`,
который читается заново на каждый диалог).

## Что не входит (по ТЗ тестового)

- интеграция с реальными данными/CRM;
- платёжные и банковские сценарии;
- полноценная БД — лиды хранятся в плоском `leads.json` (в `.gitignore`,
  создаётся автоматически), для прод-версии легко подключить БД или Google Sheets.
