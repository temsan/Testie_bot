# CLAUDE.md — контекст для продолжения работы

## Что это за проект

Тестовое задание: Telegram-бот квалификации лидов (`bot.py`, `config.py`,
`storage.py`, `admin.py`). Правила ниши и скоринга — в `config.py`, живой
конфиг с учётом правок из `/admin` — через `storage.get_config()`.

## Текущая задача (в процессе, не завершена)

Пользователь хочет **второго** бота — квалификация лидов через **Avito
Messenger**, работающего через **браузерную сессию пользователя в Chrome**
(уже залогинен как продавец "Testie_bot" на avito.ru), а не через
официальный API (у Avito Messenger API нет мгновенного доступа — см. README).

### Согласованная архитектура

1. **Не** ручной цикл через Claude Code + claude-in-chrome на каждый тик —
   слишком медленно/дорого для постоянного мониторинга.
2. **Да** — отдельный автономный Python-скрипт (условно `avito_bot.py`):
   - Playwright, подключается к уже открытому Chrome пользователя через
     CDP (`chromium.connect_over_cdp`) — переиспользует существующую
     авторизованную сессию Avito, повторный логин не нужен.
     Пользователю нужно будет запускать Chrome с флагом
     `--remote-debugging-port=9222` (это ещё предстоит согласовать/задокументировать).
   - **Предпочтительно** — не эмулировать клики в DOM, а сначала
     реверс-инжинирить сетевые запросы веб-клиента Avito Messenger (какие
     XHR/fetch запросы уходят при открытии списка чатов, чтении сообщений,
     отправке сообщения) и дёргать эти эндпоинты напрямую по HTTP с
     cookies/заголовками из той же сессии. Это надёжнее, чем селекторы DOM.
   - LLM-классификация свободных ответов лида (бюджет/сроки → один из
     вариантов в `config.py`) через **OpenRouter**, бесплатная модель.
     ⚠️ Пользователь присылал ключ OpenRouter в чате открытым текстом —
     он **нигде не сохранён** ни в файлах, ни в git. Нужно заново попросить
     ключ (или взять из истории чата) и положить в `.env` как
     `OPENROUTER_API_KEY` — `.env` уже в `.gitignore`.
   - Скоринг (сумма весов бюджет+сроки ≥ порога) считается **детерминированно
     в Python** по `config.py`/`storage.py`, а не LLM — LLM только
     классифицирует свободный текст в один из готовых вариантов ответа
     (budget_options / timeline_options), чтобы не полагаться на бесплатную
     модель в математике.
   - Состояние диалогов по каждому чату (стадия, накопленные ответы,
     последнее увиденное сообщение — для защиты от повторной обработки)
     хранится в `avito_state.json` (в `.gitignore`, не коммитится).
   - Алгоритм по стадиям (NEED → BUDGET → TIMELINE → CONTACT → DONE)
     подробно описан в **`AVITO_BOT_PLAYBOOK.md`** — актуален, скрипт должен
     реализовывать именно эту логику.

### Важное ограничение среды (обнаружено в этой сессии)

Продолжение работы шло в **облачной (remote/cloud) сессии** Claude Code —
она выполняется в изолированном контейнере, а не на машине пользователя.
Из этого следует:

- **Нет доступа к Chrome пользователя.** `chromium.connect_over_cdp` на
  `localhost:9222` работает только если сам скрипт `avito_bot.py`
  запускается на машине пользователя — из облачной сессии этот порт не
  виден.
- **Нет доступа к claude-in-chrome** в этой сессии — соответственно,
  снять реальные network-запросы Avito Messenger вживую в этой сессии
  оказалось невозможно.
- Пробовали поднять headless Chromium прямо в облачной песочнице
  (Playwright, локально к песочнице) — но исходящий трафик там идёт через
  policy-proxy окружения, и `avito.ru`, и (отдельно проверено)
  `openrouter.ai` заблокированы политикой доступа этой среды (403 на
  CONNECT). Обходить прокси сторонним прокси-сервером не стали —
  запрещено правилами безопасности сессии, плюс лишний риск для учётных
  данных.
- Пользователь присылал в чат реальный пароль от аккаунта Avito и повторно
  прислал ключ OpenRouter — **ни то, ни другое нигде не сохранено** (ни в
  файлах, ни в git). Ключ OpenRouter по-прежнему нужно положить в
  `.env` (`OPENROUTER_API_KEY`), но это должно быть сделано **на машине,
  которая реально будет запускать `avito_bot.py`** — не в облачной сессии,
  так как там всё равно нет доступа ни к Avito, ни к OpenRouter.
  Пароль Avito пользователю стоит сменить, раз он был отправлен открытым
  текстом в чат.

**Вывод**: реверс-инжиниринг реальных network-эндпоинтов Avito Messenger
может быть сделан только (а) локальной сессией Claude Code/claude-in-chrome
с доступом к браузеру пользователя, либо (б) самим пользователем через
DevTools → Network с последующей передачей найденных запросов (HAR или
описание) в чат.

### Следующие шаги при продолжении

1. **На машине пользователя** (не в облачной сессии): запустить Chrome с
   `--remote-debugging-port=9222`, залогиненный на avito.ru как продавец.
2. Либо (а) через локальную сессию Claude Code/claude-in-chrome снять
   реальные network-запросы Avito Messenger и переписать `avito_bot.py` на
   прямые HTTP-вызовы вместо DOM-селекторов (надёжнее); либо (б) прогнать
   текущую DOM-версию `avito_bot.py` на реальном тестовом лид-чате (не
   системном) и по ошибкам/DevTools поправить `SELECTORS` в файле.
3. Положить `OPENROUTER_API_KEY` в `.env` на этой же машине (не в
   облачной сессии) и сменить пароль от Avito, если ещё не сменён.
4. Протестировать полный сценарий NEED→BUDGET→TIMELINE→(CONTACT) на
   реальном лид-чате, проверить, что системный чат «Поддержка Авито»
   игнорируется.
5. Согласовать с пользователем итоговую модель OpenRouter и интервал
   поллинга, при необходимости поправить дефолты/`.env.example`.
